# `agent-os-import-adopted`

Captured 2026-09-25 when `agent-os init` (0.6.0) was run on this repository (T120). It is
kept because it is the worst case for T113 and it happened for real, not because anyone
designed it.

agent-os adopted a repository that Rulegate already owned, and got both directions wrong:

- **It imported Rulegate's generated output as its source.** Every
  `input/.agent-os/rules/*.md` is a section of the generated `CLAUDE.md`, with Rulegate's
  `<!-- generated by rulegate; edit .rulegate/ instead -->` banner copied into the rule body,
  and the canonical `.rulegate/rules/` frontmatter (`description`, `order`) gone.
- **It stacked its own banner on a Rulegate artifact.** `input/AGENTS.md` carries the
  agent-os banner above Rulegate's, so each tool now calls the file the other's.

It also wrote `input/.gemini/settings.json`, pointing Gemini CLI at `AGENTS.md` as well as
`GEMINI.md`.

With `.rulegate/` gone, the only copy of these rules is Rulegate's own rendering of them, and
importing it would make `.rulegate/rules/` out of output that has already lost its
frontmatter. So `init` **refuses**: every `.agent-os/` source that carries Rulegate's banner
is an error, nothing is written, and the hint is to restore `.rulegate/` from git. A file
carrying **either** banner is derived, never a second source.

There is no `expected/`: the expected result is the refusal. The assertions live in
`packages/cli/test/interop-import.test.ts` and `packages/cli/test/init.test.ts`.
