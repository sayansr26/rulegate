# `agent-os-import`

Not a fixture yet: `seed/` is raw material for T113, captured 2026-09-25 when `agent-os init`
(0.6.0) was run on this repository. It is kept because it is the worst case for T113 and it
happened for real, not because anyone designed it.

agent-os adopted a repository that Rulegate already owned, and got both directions wrong:

- **It imported Rulegate's generated output as its source.** Every `seed/.agent-os/rules/*.md`
  is a section of the generated `CLAUDE.md`, with Rulegate's
  `<!-- generated by rulegate; edit .rulegate/ instead -->` banner copied into the rule body,
  and the canonical `.rulegate/rules/` frontmatter (`description`, `order`) gone.
- **It stacked its own banner on a Rulegate artifact.** `seed/AGENTS.md` carries the agent-os
  banner above Rulegate's, so each tool now calls the file the other's, and `rulegate check`
  reports it as hand-edited.

It also wrote `seed/.gemini/settings.json`, pointing Gemini CLI at `AGENTS.md` as well as
`GEMINI.md` — a file Rulegate did not generate.

The directory is `seed/`, not `input/`, on purpose: `packages/cli/test/lint-fixtures.test.ts`
lints every `input/` it finds, and `pnpm fixtures:update` picks up any directory with both
`input/` and `expected/`. T113 turns this into `input/` + `expected/` fixture-first, and must
treat a file carrying **either** banner as derived, never as a second source. See T120.
